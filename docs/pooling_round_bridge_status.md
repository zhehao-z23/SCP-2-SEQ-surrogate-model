## 1. 新 C 标签已有真实可用接口，不需等待全量结束

Byte 执行入口为 `${PRODUCTION_RUN_ROOT}/queue.sqlite`。只读连接的快照为 complete=6,753、failed=119、pending=29,591、publishing=10、running=16、science_complete=4；这些是动态队列状态，**不是本轮全量标签验收**。

生产 `EXECUTION.md` 规定有效入口为 complete＋archive_receipt＋accepted `C_labels/vectors.npz`，不能仅凭 staged compact descriptor。实际接受代码位于 `project/code/C_label_store.py`，`accept()` 绑定科学身份、实际归档、命名小型标签文件 hash；`load_success()` 返回 C_sequence/C_sha256、coverage_OC、corrected_area_p、bins、协议与接受收据。

对 ordinal 最前的三条 complete 做了有界抽查（具体样本身份仅保留在私有执行记录）：

- 实际存在 `controller/records/C_labels/<scientific_key>/<stage-key>/accepted_<result-id>.json`，均为 `electro.C_label_acceptance.v2`、accepted=true；请求输入均为 view=C。
- scientific_key 与队列一致；接受收据中的 archive **path 和 sha256** 与 queue 包装内对应字段一致，实际 archive.json 的 hash 也一致。直接比较两种不同层级的整个字典不合适，本次按其引用身份核验。
- vectors.npz hash 与stage一致；corrected_area_p均为63维、有限非负，和1的最大误差9.99e−16；`sqrt_p²−p` 最大2.78e−17；62个内部箱界范围为[−20.0342930,24.7579106] kBT/e。
- 这是接口与三例轻量标签核验，没有重新验证整套大归档，也不代表6,753条均已通过本轮逐条核验。抽查样本按队列顺序选取，不是代表性科学面板。

因此“没有新标签可用”已被否定；但不能据此马上宣称历史初始化比较具备独立评价资格。

目前尚无已核验的“本轮旧Atlas监督组 → 新C受保护闭包”的排除表或可执行fold-specific初始化清单。C95计算去重不是低同源验证分组；旧T/U组的无交叉也不能自动补齐新C所有候选/备选关系。

可以并行准备明确曝光的开发桥接快照：从已接受条目选取长度/覆盖分层的面板，逐条绑定C、标签、协议和身份，建立对旧监督样本的精确序列/同源关系及相应训练排除。其用途与未来正式保护集必须分开，不能把本轮现成权重称为已合法的正式折初始化。若采用完整新C合同，则需对应关系完成证据；若另设有限开发面板，必须明确搜索范围、漏检限制和曝光，不能继承不存在的全域隔离保证。

建议本轮优先把计算用于已有资格完整的Atlas读出实验；初始化分支具体卡在上述映射，不是“等待全量标签”。同时可先准备小型已接受标签接口和下游输出头重置规则。旧p与新p的箱界及测度不同，不能直接逐维比较两个标签作为迁移真值差；冻结pLM时迁移的是实际训练过的读出模块。
