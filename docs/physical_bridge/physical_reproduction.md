# Physical bridge source archive

One fixed-coordinate AF development object has completed its own eight registered numerical sensitivity checks and passed the main integrity audit, independent final audit and immutable development-only acceptance. This is not an independent reproduction package, experimental accuracy claim, final protected test, production release or all-AFDB qualification. Actual execution and portable archive hashes are separated in `source_archive_provenance.json`.

## Required private execution environment

The recipe imports an existing controlled production project. It requires its geometry and chemistry modules, native APBS/NanoShaper execution adapters, pinned scientific Python/runtime, local-map preparation, sampler, representation exporter, attempt ledger, resource reservations and protocol/acceptance contracts. `production_dependency_boundary.json` pins selected direct imported modules and contracts by their existing project-relative locations and SHA-256. It does not copy those modules.

That inventory is **not a transitive dependency closure**. Native executables, their runtime manifests, vendored chemistry/runtime assets, all indirect imports and the actual shared-bin resolution must be supplied and verified in the original controlled environment. Their interfaces and source hashes alone are insufficient to reconstruct a complete independent package. No production controller or production state may be modified by this recipe.

Private case inputs must bind the structure bytes, selected chain/model, coordinate-derived sequence, PQR, complete retained surface, area measure and physical protocol. A public identifier or a finite probability vector is insufficient qualification. Source inputs and all role restrictions remain private and mandatory. Provisionally protected candidates must not be passed to this development runner.

## Portable path interface

The archive replaces machine paths with `--production-project`, `--bridge-root` and, for nested parallel execution, `--heavy-root`. Spawned workers inherit equivalent `BRIDGE_PRODUCTION_PROJECT`, `BRIDGE_RUN_ROOT` and `BRIDGE_HEAVY_ROOT` variables. Case selection remains an explicit `--case CASE_KEY`; no actual case identifier appears in this archive.

For example, after installing the separate verified dependencies and staging authorized private inputs in a **fresh** development workspace:

```sh
python bridge_physical_run.py \
  --production-project "$PRODUCTION_PROJECT" --bridge-root "$BRIDGE_ROOT" \
  --case "$CASE_KEY" --variants base --plan-only
```

The path adapter must be beside the archived files. It does not grant execution authority or validate a new machine's resource allocation. Historical authority prose in the original runner is replaced by a neutral archive statement. Consequently these portable copies must not be used to overwrite or resume the original already-bound execution directory: its historical code and contracts remain immutable. A new reproduction requires new local path/authority/resource bindings and receipts.

The portable `bridge_physical_run.py` CLI explicitly rejects any `--variants` list containing `further`, including plan-only requests. Its inherited numerical functions remain unchanged for provenance, but their old direct coarse-to-0.0625 route is not an accepted entry point for this study. Only `bridge_physical_further_parallel.py` may generate the recorded further-reference workflow, through verified intermediate-parent nesting. Final acceptance must bind that nested plan, parent-containment evidence, canonical ledger and parallel-execution receipts; a direct-route output is insufficient.

## Numerical and resource boundaries

The recorded eight comparison axes are spacing, further refinement, grid phase, rotation, surface resolution, expanded domain, parent-grid refinement and overlap. The nested reference requires complete ownership of all original queries and verified interpolation support from its intermediate parent fields. Whole-surface area distributions are retained; no clipped or subsampled surface proxy substitutes for the target. Comparison thresholds in the code are historical stage requirements, not proof of experimental accuracy or general AFDB validity.

The geometry revision changes a diagnostic probe distance according to a fixed global clearance bound. It must preserve mesh, PQR, area weights and coherent normal bytes. It does not certify absence of every possible self-intersection, and it does not turn a previously failed record into an original success. Explicit admission records are required.

The archived nested executor retains its historical resource constants and canonical attempt cap. Its CPU contract describes four logical CPUs comprising two SMT pairs, with one native APBS thread per field and at most two in-flight fields. These are two physical cores, not four. The production audit established nonoverlap with registered science/publication worker cores under the observed runtime; control/backup helpers may still share scheduling. No OS-exclusive partition or permanently free cores are claimed. A new environment must independently establish its own allowed allocation and fail closed on changed production bindings or overlap.

## Same-field measure contrast

[same-field measure comparison](../../experiments/bridge_20261106/physical/results/measure_contrast_summary.json) is an independently reviewed anonymous derivative of a completed local comparison on one exposed PDB method-development reference. Existing eight-axis numerical validation under the historical method contract does not establish current geometry-v3 admission, a production release, a new blind test or AF instance qualification. Only the mathematical probability measure changes in this contrast: identical frozen corrected phi, mesh and bins, normalized incident-triangle area versus uniform vertex weights. It does not isolate the complete historical-to-new-target change or causal effects of structural source.

The measure script uses NumPy and the Python standard library. Its original execution was local Python 3.12.14 / NumPy 2.3.5. Supply `--inputs PRIVATE_DIRECTORY --manifest-sha256 PIN --output PRIVATE_RECEIPT --public-output REVIEW_CANDIDATE`. The private directory must contain `input_manifest.json` with `case` and a `files` mapping that pins SHA256 for `phi.npy`, `weights.npy`, `shared_bins.json`, and `sample_record.json`. Inputs and the source sample record must already be authorized and linked through the frozen qualification evidence. None is distributed here. The script verifies those fixed bytes, uses unpickled NumPy arrays, checks normalization, and calculates exact empirical CDF distances after collapsing ties. It launches no solver or model.

The executed source SHA and portable archive SHA differ only because the archive's public serializer removes absolute single-object target summaries, limits effect summaries to mean and positive-fraction differences, and adds a tail limitation. Numerical calculation and private receipt construction are unchanged. The historical execution was not rerun for this archive. The reviewed summary separately received the same privacy filtering. A one-reference example with no observed open-tail mass cannot assess tail differences or tail generalization. Public candidates still require review; an automatically written candidate is not publication approval.


## Completed final evidence

See `physical_final_report.md` and the anonymous [anonymous summary](../../experiments/bridge_20261106/physical/results/summary.json) archive for eight sensitivity differences, nine-variant sampling integrity, 94 completed fields, 37/2/29 stage history, and receipt hashes. These are registered composite numerical sensitivity checks, not isolated single-factor causal interventions or a continuous-limit error bound. Base/refined outer parent spacings are about 0.85/0.472222 angstrom, with fine spacings 0.25/0.125; the values 1/0.5 were requested maxima. Local box, partition and halo changes remain coupled. The final nested comparison uses intermediate 0.125 to 0.0625 spacing.

The source closure update is recorded in `gate_source_delta.md`. The prior prepared source and executed v1 summary remain private historical records. Final v2 omits the sum of per-field peak RSS; per-field peak RSS is not aggregate host peak, and APBS task-seconds are not CPU accounting or total pipeline elapsed time.
